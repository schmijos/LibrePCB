## 3. Placement and routing approach

- **Placement:** U1 (DIP-8, "hand soldering" footprint) sits in the middle at (20,15), rotated 90°. The bottom row is pins 1–4 (GND, TRIG, OUT, RESET), the top row pins 8–5 (VCC, DIS, THR, CV).
  - J1 at (3,15), LED1 at (36,8) rotated 270°.
  - R1 and R2 side by side along the top edge, so the DIS node between them sits right above pin 7.
  - C3 just above pin 8, C2 right of pin 5, C1 right of the chip, R3 along the bottom edge feeding the LED.
- **Routing:** I planned the coordinates by hand from the pad positions that `board_place_device` returns, then used `board_route` with corner points.
  - TRIG–THR runs on the bottom layer under the DIP body; C1.+ joins it with a T-junction on that trace.
  - VCC to RESET (pin 4, the diagonal pin) runs on the bottom layer around the chip to J1.1.
  - Everything else is on top.
- **Checks:** No route reported a clearance violation. I checked the result with renders of each copper layer.
- **Silkscreen:** I moved the part texts so they don't overlap, and added the board title `{{PROJECT}} {{VERSION}}` and +/− marks at J1.

## 4. Tool gaps

1. **No net label on an existing wire.** I wanted R1.2–R2.1 joined by a visible wire that also carries a "DIS" label. `schematic_draw_wire` makes an unlabelled wire, and nothing can add a label to it later. The wired version therefore showed no net name. I went back to labels only and spaced the resistors apart so the labels don't overlap (see section 5).
2. **No way to view a library element.** I could only check the symbol (pin side, text placement) after placing it in a schematic. There is no `render_symbol` or `render_footprint`.
3. **`library_get` on a component doesn't return signal roles or required flags,** so I couldn't confirm the roles I set.
4. **`symbol_create` has no pin options:** no inverted or clock marks (e.g. an inverted RESET), no hidden pins, no extra graphics. Impact is only on how the symbol looks.
5. **No tool to re-run the library check** on an existing element. Checks only come back at creation time.
6. **No help for symbol orientation.** The Resistor, Capacitor and LED symbols are vertical at rotation 0, and the tool descriptions don't say so. I found out with a render and placed them again. `schematic_add_part` does return pin positions, which helped.

## 5. Workarounds and their downsides

- **DIS net:** After `schematic_draw_wire` R1.2→R2.1 created N1, adding U1.DIS through `schematic_connect` failed. `net_rename` N1→DIS merged the nets. But the wire then had no label, so I disconnected it and used separate labels. Downside: the schematic shows no direct wire between R1 and R2.
- **Text overlaps:** The first renders had overlapping labels: R1.1 "VCC" collided with R2.2 "TIMING", and later two "DIS" labels would have been very close. I respaced the parts so no label overlaps. Downside: the schematic layout is looser than it needs to be.
- **Assumed signal roles:** VCC and GND power (required), TRIG and THR input (required), RESET input, OUT output, DIS open-drain, CV passive.
- **Other assumptions:**
  - Pin numbering is the standard NE555 DIP-8, taken from the brief.
  - Default trace width 0.5 mm for all nets, power included, since the LED current is under 20 mA.
  - LED anode is the round pad and cathode the square pad, as the footprint has them.

## 6. Bugs or confusing behaviour

1. **`schematic_connect` contradicts its own description.** The description says "Pins in a net with an automatic name like 'N1' join the net of the given or forced name." But after `schematic_draw_wire {"from":"R1.2","to":"R2.1"}` returned `{"net":"N1"}`, this call failed:
   `schematic_connect {"net":"DIS","pins":["R1.2","U1.DIS"]}` → `TOOL ERROR: The pins are already connected to different nets ('N1' and 'DIS'). Disconnect them first.`
   `net_rename {"net":"N1","name":"DIS"}` then merged them fine. So the auto-merge works in `net_rename` but not in `schematic_connect`, even though both descriptions promise it.
2. **BOM leaves U1's Value empty.** In `555_Blinker_v1_BOM_Std.csv` the U1 row is `1,U1,DIP762W55P254L965H533Q8,,NE555P,Texas Instruments`, while the PnP file and the schematic show Value "NE555P". This is probably intended (value equals MPN, so it is deduplicated), but it is surprising.
3. **"layers" render is hard to read.**
   - Top traces in the combined view look bluish/outlined, because the bottom plane's clearance outlines show through.
   - J1's pads are drawn grey while the other THT pads are green.
   - Rendering one copper layer at a time was needed to read the routing.
4. **Unclear "stop mask" wording at the board edge.** The first DRC warning, "Clearance silkscreen text ↔ stop mask < 0.127 mm" at x≈39.94, came from the LED1 name at (39.7,8), but the location sits right on the board edge. The message doesn't say whether "stop mask" means the board edge, so I had to guess what to move.
5. **Placement is out of step with the tool docs.** The `project_create` description says the board starts at 100×80 mm, and it is easy to miss that `board_place_device` accepts parts outside the outline before you shrink it. The DRC did not show this up because I set the outline first. Not a bug, just ordering to be aware of.

## 7. Suggestions, ranked by impact

1. Make `schematic_connect` merge auto-named nets (N1) into the named net, as its description says. Also add a way to attach a net label to an existing wire or segment, or let `schematic_draw_wire` take an optional net name and label.
2. Add `render_library_element` (symbol or footprint PNG) so symbols and pad maps can be checked before use.
3. Return signal roles and required flags from `library_get` for components, and add a `library_check` tool for existing elements.
4. Document the default symbol orientation, or report it in `library_get` (e.g. "pins vertical at rotation 0").
5. Add pin options to `symbol_create`: inverted or clock marks, plus name and value text positions.
6. In DRC messages, name the conflicting objects (e.g. "LED1 name text vs board edge or stop mask") as well as the coordinates.
7. Make the "layers" render style easier to read: clearer distinction between top and bottom layers, consistent pad colours.
8. Note in the BOM output, or in the `output_jobs_run` result, when Value is suppressed because it equals the MPN.
