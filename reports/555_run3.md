## 3. Placement and routing approach

I planned everything by hand from the pad coordinates that `library_get` and `board_place_device` return.

**Placement:**
- U1 at (17, 13).
- R1 at (17, 26.5) and R2 at (17, 22.5), R2 rotated 180° so that R1.2 and R2.1 (both DIS) face each other at x = 22.08.
- C3 (0805) at (19.5, 19.5), rotated 180°, so pad 1 (VCC) sits about 2.7 mm from U1 pin 8.
- C1 at (27, 13) next to pins 6 and 7, C2 at (25, 8.6) next to pin 5.
- R3 at (24, 4) below U1, J1 at (3, 15) and LED1 at (35, 15).

**Routing:**
- Top layer:
  - DIS: R1.2 → R2.1 → down x = 23.5 → pin 7.
  - TIMING: R2.2 → down x = 10.2 → pin 2, then diagonally between the DIP pad rows → pin 6 → C1.+.
  - CV: pin 5 → C2.1.
  - OUT: pin 3 → down x = 15.2 → R3.1.
  - LED_A: R3.2 → LED1.A.
  - VCC: J1.1 → R1.1, and C3.1 → pin 8.
- Bottom layer (VCC only): J1.1 → y = 19 → pin 8, and RESET pin 4 → between the pad rows → pin 8. Keeping the bottom almost empty leaves the bottom GND plane mostly in one piece.

Every `board_route` quick check reported 0 violations. I then rearranged the silkscreen texts: resistor values inside the bodies, names beside the parts. I added "{{PROJECT}} {{VERSION}}" and a "+" marker at J1.

## 4. Tool gaps

1. **No T-junctions on schematic wires.** `schematic_draw_wire` only goes from pin to pin. To join a third pin to a wire I had two options: overlapping wires, or net labels. I used labels for every U1 pin. The schematic is valid but less readable than a wired one.
2. **No control over net label position or orientation.** `schematic_connect` always puts a short stub plus label in the pin direction. Two labels on facing vertical pins (R2.2 and C1.+) rendered as "TIMINGTIMING". I had to push C1 and its GND symbol down until the labels no longer touched. Impact: extra iterations and a stretched-out schematic.
3. **No way to see a symbol's graphics or its texts.** `library_get` for a symbol returns only the pins: no body, no name/value text positions. `library_get` for a component doesn't return categories or signal roles. I could only confirm "name above, value below" by placing the part and rendering it.
4. **Category hierarchy not shown.** `library_search` with type componentCategory returns names without their parent path. I couldn't confirm that "Timers, Oscillators" sits under "Integrated Circuits › Clock, Timing"; I relied on it being the only match.
5. **Some layers can't be rendered.** `render_board` offers no stop mask or solder paste layers, so I couldn't look at the stop-mask clearance behind the DRC warning.
6. **DRC messages don't name the offending item.** The silkscreen warning gave two locations, center and size only. I had to work out that the cause was the C3 name text (at (19.5, 18.075), rotated 180°) near U1 pin 8, by comparing against `board_list_items` texts.

## 5. Workarounds and their downsides

- **Net labels instead of wires** for multi-pin nets: the schematic shows connectivity by label, not by drawn wire.
- **Wider part spacing** to keep labels from colliding: the schematic is spread out more than needed.
- **Silkscreen layout by hand**, by computing text extents in my head. Without text bounding boxes in the tools, that is trial and error.

## 6. Bugs and confusing behaviour

1. **Trace IDs change after a later, unrelated route from the same pad.**
   - Call: `board_route {"from":"J1.1","to":"R1.1","layer":"top","points":[[5,18.27],[5,24],[7.5,26.5]]}`.
   - Response: `{"traces":["trace:3ed59c72-…","trace:bdf8db1c-…","trace:d51c3883-…","trace:f67f6c9a-…"],"violations":[],"width":0.5}`.
   - Next call: `board_route {"from":"J1.1","to":"U1.8","layer":"bottom","points":[[5.73,19],[20.81,19]]}` (3 segments).
   - Response: 7 IDs, among them `trace:59629cc1`, `bd0e1811`, `81b820d7` and `171c1be7`.
   - `board_list_items` showed those 4 are the *top-layer* J1.1→R1.1 traces with new IDs. The 4 IDs from the first call no longer exist.
   - So routing from a pad that already has a trace re-creates that trace under new IDs and mixes them into the response. Any ID an agent stored becomes invalid, and the response suggests it created 7 traces when it created 3.
2. **BOM "Value" column empty for U1.** The BOM row reads `1,U1,DIP762W55P254L965H533Q8,,NE555P,Texas Instruments`, while the pick&place file and the schematic show value "NE555P". It is probably dropped on purpose because value equals MPN, but it looks like missing data.
3. **Rotation conventions differ between symbols.** `rotation: 90` turned the resistor vertical but the capacitors horizontal, because their default orientations differ. Nothing in `library_get` says how a symbol is oriented, so I needed extra move calls. `part_get` returning pin positions made it easy to recover.
4. **Unknown layer name only fails at call time.** `render_board` with `"board_stop_mask_top"` returned `TOOL ERROR: Unknown layer … Available: …`. The list is helpful, but stop mask is simply not available (see gap 5).

## 7. Suggestions, ranked by impact

1. Keep trace IDs stable when routing from a pad that already has traces, and return only the newly created IDs. This is bug 1.
2. Let `schematic_draw_wire` end on an existing wire or junction, creating a T-junction, and give `schematic_connect` an option for label position or rotation.
3. Name the offending items (IDs, text content) in DRC and ERC messages, not only their locations.
4. Extend `library_get` for symbols to return the body, texts and default orientation. Return categories and signal roles for components, and the parent path for categories.
5. Add stop mask and paste layers to `render_board`, and bounding boxes to texts in `board_list_items`.
6. Make it clear in the BOM output (or the tool docs) why the value is blank when it equals the MPN.

## Assumptions

- **Signal roles for the 555:** VCC and GND are required power pins, TRIG, THR and RESET are required inputs, OUT is an output, DIS is open-drain and CV is passive.
- **Capacitor components:** "Capacitor Bipolar" (signals 1 and 2) for C2 and C3, "Capacitor Unipolar" for C1.
- **Default design rules:** 0.5 mm traces, no net classes.
- **Schematic note:** I added a text with the blink-rate formula.
