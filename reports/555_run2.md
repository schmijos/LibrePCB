The 555 LED Blinker is finished and uses only the MCP tools. The library parts, schematic, board and production data all exist and the project is saved.

- **Library:** I created "My Parts" (description "Parts for the 555 tutorial", depends on LibrePCB Base). The symbol NE555, component NE555 and device NE555 DIP-8 (TI NE555P on DIP762W55P254L965H533Q8) all passed their library checks with 0 messages.
- **Project:** "555 Blinker" is at `BLIND/projects/555_Blinker/555_Blinker.lpp`. It has an A4 Landscape frame, all 9 parts with their values, a VCC and a GND supply symbol, and 7 nets. `netlist_get` matches the brief, and TIMING is named and visible as net labels.

Every non-GND net is routed with 0.5 mm traces, and there are GND planes on top and bottom. No vias were needed: every GND pad connects through a plane, either by thermal relief (THT on both layers) or on the top plane (C2/C3 SMD pads).
- **Final status:**
  - ERC: 0 messages.
  - DRC: 0 messages. The first run gave 2 silkscreen-text warnings; I fixed them by moving texts, not by approving them.
  - Board: 0 unplaced parts and 0 unrouted connections.
- **Output:** `output/v1/` contains the Gerbers (copper, mask, paste, silk, outline), PTH/NPTH drill files, BOM CSV, top and bottom PnP CSVs, schematic and assembly PDFs, a `.zip` and a `.lppz`. The schematic PDF shows U1 = NE555P.

## 3. Placement and routing approach

I rotated U1 by 90° so both pad rows run horizontally. That puts VCC (pin 8) top-left near J1, DIS, THR and CV along the top, and OUT bottom-middle heading toward R3 and the LED.

- **Top row:** R1 and R2 lie horizontally above U1, one above the other, so R1.2, R2.1 and pin 7 make a short vertical DIS run.
- **Right side:** C1 (radial) sits to the right of R2, and C2 (0805) beside pin 5.
- **Bottom and edges:** R3 is horizontal at the bottom and leads diagonally to the LED at the right edge. J1 is at the left edge.
- **Crossings:** inside the DIP channel between the pad rows, the RESET→VCC strap runs on top (pin 4 → pin 8 with two corners) and TRIG→THR runs straight on the bottom layer.

Before routing, I worked out clearances by hand from the pad geometry that `library_get` and `board_place_device` return. Every `board_route` came back with no violations. I then added the two planes and moved silkscreen texts to clear DRC warnings and overlaps. Finally I added "+" and "−" next to J1 and a `{{PROJECT}} {{VERSION}}` label.

## 4. Tool gaps

1. **No way to place a net label on its own or on a wire.**
   - Tried: `schematic_draw_wire` between R1.2 and R2.1 (and R2.2 to C1.+), then `schematic_connect` with net names.
   - Missing: `schematic_connect` skips pins that already have a wire, so no label appears at that node. You can't see on the sheet that those wires belong to DIS or TIMING.
   - Impact: I had to delete the wires and use labels only, which reads less clearly.
2. **No control over where labels go.** Labels from `schematic_connect` always sit on a short wire stub. When two pins are close (R1.2 and R2.1, 5 mm apart) the labels overlap, and there is no parameter for label position or direction. I worked around it by spreading the parts apart.
3. **No dedicated frame tool, and `project_create` adds no frame.** I only found the frame by searching for components with "frame". A hint in `project_create` or `schematic_add_page` would help.
4. **Library metadata can't be read back.** `library_get` and `library_search` don't return the categories, or for components the description/role/required flags I set, so I could not confirm the category requirement.
5. **Symbol rotation conventions are undocumented.** At rotation 0 a resistor is horizontal while capacitors and the LED are vertical. I had to place each part, read the returned pin positions and re-rotate it. The pin-position output did make this workable.
6. **Unclear text anchors.** Docs say footprint texts are "often centered" on their anchor, so you can't predict silkscreen text extents without rendering. A bounding box in `board_list_items` would help.

## 5. Workarounds and their downsides

- **Labels instead of wires** for DIS and TIMING. Downside: the schematic is all labels, and connectivity is less obvious to a human reader.
- **Moved C1 and R2 apart in the schematic** so their labels don't overlap. Downside: a looser layout.
- **Hand-calculated clearances** for the traces inside the DIP channel. They worked and the quick check confirmed them, but this is error-prone.
- **LED value set through the COLOR attribute** ("red"). Picking the "Red" device does not fill it in.

## 6. Bugs or confusing behaviour

- **BOM value for U1 is empty.** `output_jobs_run` produced `assembly/555_Blinker_v1_BOM_Std.csv` with the row `1,U1,DIP762W55P254L965H533Q8,,NE555P,Texas Instruments`. The Value column is empty, even though `part_get` and the schematic show the value NE555P. Probably intentional when value equals MPN, but it looks like missing data.
- **First DRC run flags default text placement.** `drc_run` reported "Clearance silkscreen text ↔ stop mask < 0.127 mm" at (39.939, 10–13) and (21, 29.914). The library's default text positions put the LED1 name (rotated 270° at x=39.2) and the R2 name at the board edge. This is expected behaviour, but `board_place_device` doesn't warn about it.
- **`project_create` returns plain text.** It answers only "Project created and opened." with no JSON (path, board or schematic names), unlike the other tools.
- **Layer names in `render_board`.** `board_legend_top` excludes part names and values (separate layers `top_names`/`top_values`), and the realistic render doesn't show values. This is not obvious.
- **`schematic_disconnect` hides a side effect.** Disconnecting R1.2/R2.1 left U1.DIS alone in net DIS, which is correct, but the response is only "Disconnected." and doesn't say which nets changed.

## 7. Suggestions, ranked by impact

1. Add `schematic_add_label` (on a pin, wire or point, with direction), or make `schematic_connect` add a label to pins that already have wires.
2. Return categories, description and signal roles from `library_get` for library elements so the result of creation can be checked.
3. Document symbol rotation per component in `library_get`, for example the pin offsets at rotation 0, so placement doesn't need trial and error.
4. Have `project_create` add a default schematic frame (option `frame: "A4 Landscape"`), or offer a `schematic_set_frame` tool.
5. Include text bounding boxes in `board_list_items` and warn in `board_place_device` when footprint texts fall outside the board.
6. Explain or fix the empty BOM Value column when the value equals the MPN.
7. Make `project_create` return JSON (path, schematics, boards) like the other tools.
